# Android 16 KB page sizes (Play requirement)

Google Play requires apps targeting **Android 15 (API 35) or higher** to support
16 KB memory page sizes on 64-bit devices. From **February 1, 2027** you cannot
release an update that does not.

If you read November 1, 2025 or May 31, 2026 anywhere, those dates were
superseded. Confirm the live date on
[developer.android.com/guide/practices/page-sizes](https://developer.android.com/guide/practices/page-sizes)
before trusting this file — the deadline has already moved twice.

## 1. Does this apply to you

It applies to **native code only**. An app whose every line, library, and SDK is
Java or Kotlin already complies.

This app is not in that category. React Native ships native `.so` libraries, and
so do several modules in `app.json` (`expo-sqlite`, `react-native-reanimated`,
`react-native-svg`, `react-native-purchases`, `@sentry/react-native`). So the
requirement applies, and the question is only whether the versions you ship are
already aligned.

Recent React Native and Expo SDK releases align by default. **Do not treat that
as proof.** The artifact is the proof, and a single stale transitive prebuilt is
enough to fail the upload.

## 2. Check the artifact, not the framework version

The alignment lives in the built `.aab`, so this check needs a real build. There
is nothing to check in this repo before that.

Two things must hold:

1. Every ELF `LOAD` segment in every bundled `.so` is aligned to at least
   2^14 (16384).
2. The app bundle reports `PAGE_ALIGNMENT_16K`.

After an EAS Android build, download the `.aab` and inspect it:

```bash
unzip -o app.aab -d aab-out
find aab-out -name '*.so' -print

# Per library: every LOAD segment's Align must be >= 0x4000
$ANDROID_NDK/toolchains/llvm/prebuilt/*/bin/llvm-readelf \
  --program-headers aab-out/base/lib/arm64-v8a/libreactnative.so \
  | grep LOAD
```

Google also ships `check_elf_alignment.sh` in the NDK, which is faster than
reading headers by hand. Play Console reports the bundle-level result on upload,
which is the authoritative answer.

## 3. If something is misaligned

1. Update the offending dependency first — for most React Native modules a newer
   release is already aligned.
2. If you control the native build, use **Android Gradle Plugin 8.5.1+** and
   **NDK r28+**, which default to the required alignment.
3. If a third-party prebuilt is stale and unmaintained, that is a dependency
   decision, not a build flag. Stop and discuss it — replacing or dropping the
   module is on the table.

Do not hand-edit `apps/mobile/android/`. It is generated by prebuild, and
`AGENTS.md` requires asking before touching it at all.

## 4. Test on a 16 KB device

An Android 15 emulator image can boot in 16 KB mode, and some physical devices
expose it under Settings > System > Developer options after applying updates. A
misaligned library fails at load, so the symptom is a crash on launch rather
than a subtle bug.

## 5. Where this belongs in the release flow

This is a `/app-ship` concern, checked once per release against a real build — not a
per-job check, and deliberately not part of `npm run check`, which never builds
native code.
